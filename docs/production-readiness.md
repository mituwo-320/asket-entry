## 今回の機能変更

画面の見た目を整えた前回までの変更に加えて、今回は所有者の「本番に向けた最終確認と必要な改善」という依頼に基づき、以下の動作を変更した。

| 項目 | 修正後の動作・影響 |
| --- | --- |
| 管理・運営ログイン | 固定値 `true` のCookieを廃止。環境変数のパスワードで認証し、役割・有効期限・署名を検証する。ソース内の既定パスワードを使わない。 |
| 参加者ログイン | localStorage内のIDを認証として信頼せず、HttpOnlyの署名付きCookieとDBの所有者を照合する。他人のuserId・entryId・playerIdによる読み書きを拒否する。 |
| セッション | 有効期限7日。スタッフのパスワードや署名鍵変更、参加者のパスワード再設定後は旧セッションを無効化。旧方式でログイン中の全員は再ログインが必要。401時は適切なログイン画面へ移動する。 |
| APIの権限 | 個人情報・変更・印刷用データを扱うAPIにも認証を追加。管理者専用の設定・復元などは運営アカウントから操作できない。運営で従来利用する受付・試合・印刷・読み取り専用の大型表示は利用可能。 |
| 新規申し込み | 公開中・テスト大会ではない・受付期間内をサーバーでも検証する。管理者には期間等の例外を残す。キャンセル済みを除いた定員判定、ユーザー・チーム・代表者の作成をSerializableトランザクションにまとめ、競合時は最大3回試行する。定員超過時のキャンセル待ち設定を維持する。 |
| 選手の編集 | 画面に表示していた締切をAPIでも確認する。他チーム選手の上書き、参加者による代表者区分の変更を拒否する。提出後の編集禁止、代表者削除禁止を維持する。 |
| 過去のメンバー引用 | 所有者の追加依頼により、同じアカウントの別チームから複数人を選択・編集して一括追加できる。元チームは変更しない。今回の代表者・締切・提出後制限を維持し、二重追加を抑止する。詳細は `docs/member-history.md`。 |
| チーム情報の保存 | 参加者が変更できる項目だけを保存し、古いスナップショットから入金・状態・領収書・他選手を上書きしない。チーム・代表者・プロフィールの更新は同一トランザクション。クリニック人数の不正値・上限超過を拒否する。 |
| 保存失敗時 | 運営の確認状態と管理の入金状態はHTTP成功後に表示へ反映する。ユニフォーム色を運営APIで保存可能にする。管理画面の得点・試合確定・色保存もHTTP失敗を通知する。 |
| 領収書 | 入金済みの場合のみ発行し、最初の宛名・発行日時を条件付き更新で確定する。閲覧も発行済み・未閲覧を条件に更新し、同時操作で初回記録を上書きしない。発行・閲覧の既存の一度限りというルールを維持する。 |
| バックアップ復元 | 対象大会の整合性を検査し、ユーザー更新・対象データ削除・復元を一括トランザクションにする。失敗時はロールバック。他の適当なユーザーへの付け替えを廃止。新規復元ユーザーのパスワードはランダム値となるため、本人が再設定して利用する。既存ユーザーのパスワードは変更しない。 |
| テストデータ | 空の大会一覧GETで自動的にサンプル大会を作成しない。テストチーム生成ボタンはテスト大会だけに表示する。生成前のバックアップ失敗時は削除を始めない。 |
| 大会別試合 | 大会未指定のスタッフ向け試合一覧は全大会を取得し、選択中の大会に画面で絞る。旧来の固定大会IDによる取得漏れを解消する。 |
| メール | 未設定時に送信成功を装う処理と再設定トークン等のログ出力を廃止。メールHTMLの入力値をエスケープ。送信失敗は登録を取り消さず、ログには内容・トークン・生のSMTPエラーを出さない。再設定APIはメールアドレスの存在を明かさない応答を維持する。 |
| 定期実行 | keep-alive APIは `CRON_SECRET` のBearer認証を必須にする。 |
| 公開時の検査 | TypeScriptエラーの無視を廃止。Vercel Productionビルドの開始時に必須環境変数の検査を追加し、不備があればビルドを失敗させる。ローカル・Previewはこの本番専用検査を自動強制しない。 |

参加費・保険料の計算式、請求書・領収書の印刷レイアウト、組み合わせ生成・勝ち上がり計算のルール、DBスキーマは今回変更していない。期間外の申し込みやID指定だけでの操作など、従来APIで通ってしまっていた操作は上記の通り意図して制限している。

## 2026-10-19の追加改善

- 郵便番号・住所はフォームから送られていたが、`saveUser`がDB更新に含めていなかったため、保存・空欄への変更を反映するよう修正。パスワード更新には触れていない。
- 予定・試合予定の保存はHTTP失敗を検査し、失敗時にダイアログと入力を残す。送信先とpayloadは維持する。

- 勝者演出の開始で再描画した際に終了タイマーが解除されてしまう問題を修正。開始フレームと600ms/8秒の終了タイマーを分け、演出が終了する回帰テストを追加した。
- テーマ・得点表示の保存値を外部ストアとして購読し、サーバー描画と初回表示の整合性を保つ。別タブの設定変更も反映する。自動カメラは試合数だけでなく対象試合の変更にも追従する。
- 大会切り替え時に印刷チェックの状態をリセットする。運営の対戦表は未作成時に参加数を初期候補とし、手動で選んだチーム数を再読み込みで上書きしない。
- 印刷用のページタイトルは描画中ではなくcommit後に設定する。書類本文・金額・印影の表示寸法は変えていない。
- 未使用の関数・import・変数を整理した。対戦・日程計算は固定乱数で生成・配置・スコア・勝敗・取り消し・自動結果・日程の62比較を行い、10/18の公開候補と出力が一致した。

追加テストはプロフィールの保存/クリア、予定保存失敗、領収書の同時閲覧、演出終了、別タブの設定反映、マイページの通信失敗時案内を確認する。実データ・実領収書・SMTPへは接続していない。

## 2026-10-20の分離したPreviewでの検証

- Vercel HobbyとSupabase Freeの範囲で検証環境を用意。有料のブランチ機能やプラン変更は使用していない。既存の本番環境変数と本番デプロイを維持した。
- `design/natural-entry`だけにPreview用のDB接続、セッション鍵、管理・運営パスワード、Cron秘密値、アプリURLを設定。メール送信設定を無効にし、通知先は`.invalid`を使用した。本番データはコピーしていない。
- `scripts/verify-isolated-preview.mjs`を追加。Preview環境、明示した検証DB、専用の非特権ロール、TLS、送信停止、独立した認証情報を検査してから開始する。通常ビルドへは組み込まず、対象PreviewデプロイだけのBuild Commandで`npm run build && node scripts/verify-isolated-preview.mjs`を実行した。
- 検証コード`5df67f9`で、Vercel内のNext.jsサーバーに実HTTP要求を送り、Prisma経由で検証用PostgreSQLに保存する**10項目がすべて成功**。同じコードでGitHub CIの型・241テスト・全体Lint・ビルドも成功した。

自動検証は一意な接頭辞のデータだけを作成し、終了時に削除した。手動確認用の「【検証用】ASKET CUP」は検証DBだけに残している。公開Previewの大会一覧APIがこの大会を返すことと、登録ページのHTML応答も確認した。

**検証の限界:** NodeのHTTPクライアントを使用し、通常要求にブラウザーのOriginは付けていない。別サイトOriginの拒否は検査したが、ブラウザーでの同一サイトOrigin・Cookieの自動送受信、クリック操作、狭い画面、印刷は未確認。メールを停止しているため、メール到達と再設定リンクの往復も未確認。これらはAPI/DBテスト成功で代用しない。本番DBの権限・認証情報の適合、復元可能な直前バックアップ、本番の必須設定は公開前に別途確認する。

## 2026-10-21の本番公開手順

所有者がPreviewを確認し、本番更新を明示的に依頼した。これ以前の「本番未反映・未マージ」は、その時点の記録であり、今回の公開承認前の状態を示す。

- 本番とPreviewの認証情報は分離する。既存の本番DB・メール設定は引き継ぎ、必須の認証・Cron設定を整える。秘密値と運用環境の詳細は公開リポジトリに残さない。
- 公開直前のアプリデータを同じ本番DB内の非公開領域に暗号化して保存し、復号後のハッシュと件数の一致を確認する。これは誤更新を戻すための論理コピーであり、DB全体の障害に備える外部バックアップではない。別環境への本番データ移送は行わない。
- 通常の`build`の最後に`scripts/verify-production-connections.mjs`を追加。Vercel Productionでのみ、読み取り専用トランザクションでアプリの各テーブルを確認し、SMTPの接続・認証を検査する。失敗時はビルドを失敗させる。Previewとローカルでは実行しない。
- 接続検査は本番レコードの追加・変更・削除やメール送信を行わず、秘密値・生の接続エラーをログへ出さない。SMTP認証成功は受信箱へのメール到達を保証しない。

## 実環境で揃える設定

Vercelの **ProductionとPreviewで別のDB・署名鍵・スタッフパスワード** を使う。秘密値をGitHubやチャットへ書かない。項目一覧は `.env.example` を参照する。

| 変数 | 設定内容 |
| --- | --- |
| `DATABASE_URL` | 対象環境のPostgreSQL接続URL。接続先とPrismaスキーマの一致を確認。 |
| `SESSION_SECRET` | 32文字以上の十分にランダムな秘密値。代替として `NEXTAUTH_SECRET` が使用可能。両方ある場合はSESSION_SECRETを優先。 |
| `ADMIN_PASSWORD` / `MANAGEMENT_PASSWORD` | それぞれ新しい別の強いパスワード。本番ビルド検査では16文字以上が必要。旧ソースにあった既定値を再利用しない。 |
| `NEXT_PUBLIC_APP_URL` | 本番は `https://asket-entry.vercel.app` 等の正式なHTTPS URL。Previewは実際に確認するPreview URL。再設定メールのリンク先になる。 |
| `SMTP_HOST` / `SMTP_PORT` | 実際のSMTPサーバーとポート。 |
| `SMTP_SECURE` | 465は通常true、587は通常false。利用するメールサービスの設定に合わせる。 |
| `SMTP_USER` / `SMTP_PASS` | 送信用アカウント・認証情報。送信元のドメイン認証もサービス側で確認。 |
| `ADMIN_EMAIL` | 新規・本エントリー通知の宛先。 |
| `CRON_SECRET` | 定期実行用の強い秘密値。本番検査では16文字以上。 |
| `LINE_CHANNEL_ACCESS_TOKEN` / `LINE_ADMIN_USER_ID` | LINE通知を使う場合のみ。現在の登録APIはメール通知を使用しており、この変更でLINE通知を新設していない。 |

実環境の変数を読み込める環境で `npm run check:env` を実行する。値は出力しない。形式・存在の検査にすぎず、接続成功の確認は別に必要。Vercel以外へデプロイする場合は公開手順でも明示して実行する。VercelのBuild Commandでpackage.jsonの `build` を迂回していないことも確認する。

10/19時点ではVercelの参照権限を取得できなかった。10/20には参照が可能となり、Previewブランチ専用の設定と分離DB接続を確認した。本番の秘密値を復号して流用せず、既存の本番設定は変更していない。Productionの環境検査・SMTP到達まで完了したことを意味しない。
