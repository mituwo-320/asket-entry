# 過去のメンバーから追加

2026-10-19、所有者の依頼に基づいて参加者の選手登録に追加した機能。元のチームの登録内容を変えず、今回のチームへ新しい選手として複製する。DBスキーマ・依存パッケージの変更はない。

## 使い方

1. チーム管理の選手リストで「過去のメンバーから追加」を開く。
2. 同じアカウントで登録した別チームを選び、氏名・フリガナで検索する。複数人の選択、表示中の一括選択ができ、チームを切り替えても選択が残る。
3. 必要なメンバーの「編集」で氏名・フリガナ・保険・リストバンドを変更し、「変更を反映」で一覧へ戻る。この時点ではサーバーへ保存しない。
4. 「N人をまとめて追加」で今回のチームへ保存する。一度に50人まで。追加後も通常の選手編集で変更できる。

## 操作性の改善

- 「メンバーを探す」と「選択中を確認」を切り替えられる。確認画面では、異なるチームから選んだ全員をまとめて表示し、その場で編集・選択解除できる。確認画面は任意で、少人数なら選択画面から直接追加できる。
- 確認画面には元の大会・チーム、保険・リストバンド、変更した人の「変更あり」を表示する。追加予定・保険加入・保険なしの人数も表示し、追加前の確認を助ける。
- ひらがな・カタカナ・半角カナと空白の違いを吸収して検索する。検索のクリア後は検索欄へフォーカスを戻す。この検索の変更は、サーバーの重複判定のルールを変えない。
- 選択後に閉じる・背景・Escで終了しようとすると破棄の確認を表示する。「作業を続ける」で選択と、まだ反映していないフォーム入力も保持する。保存中は引き続き終了できない。
- 下部の追加ボタンと人数表示をスクロール時も追える構成とし、狭い画面では操作ボタンを横幅に合わせる。タップ領域は44px以上、キーボードのフォーカスは明示する。
- フリガナ等が不足したときは選択中の確認画面へ移し、エラーへフォーカスを当てる。編集後は編集ボタンへ戻し、選択解除でボタンが消えたときは確認見出しへ戻す。

上記の選択横断編集、検索、未反映の入力の保持、Escと破棄の確認、フォーカス、50人到達時の操作を画面テストで確認した。ブラウザーによるサンプル画面の目視確認は接続処理がタイムアウトしたため未完了であり、実機での表示・ソフトキーボード表示時の操作は公開前に確認する。

## 編集保護・引用元の説明・一括変更

所有者の追加依頼に基づき、費用表示の追加を除く3項目を実装した。

- 選手の編集中に「一覧へ戻る」を押した場合、未反映の変更があるときだけ確認する。「作業を続ける」では入力をそのまま保持する。破棄を選ぶと今回の編集だけを取り消し、前に一覧へ反映した値は保持する。通常の選手フォームは、引用画面だけで有効にする任意の確認ハンドラーを追加したもので、他画面のキャンセル動作は変えていない。
- 「選択をすべて解除」は対象人数と編集内容が消える旨を確認する。編集済みのメンバーを個別に外すときも確認する。確認を取り消すと選択・編集内容は残る。未編集のメンバーは通常どおり直接選択解除できる。
- 引用元のラベルを「自分が過去に登録したチーム」に変更し、同じアカウントの登録履歴に限ること、同じチーム名でも別大会から引用できることを説明する。対象チームの取得・権限ルールは変更しない。
- 「選択中を確認」から保険・リストバンドを一括変更できる。対象は追加予定として選択した全員で、別チームから選択した人も含む。各項目の初期値は「変更しない」で、指定した項目だけを反映する。保険だけ、リストバンドだけの変更もできる。
- 反映前に対象人数・対象者名・変更項目・実際に値が変わる人数を確認する。変更がない設定は反映できない。設定の見直し・中止ができ、反映後は個別編集も可能。確認と反映は画面内の編集であり、最後に「まとめて追加」を押すまでAPIへ保存しない。

未選択のメンバー、今回すでに登録した選手、引用元のチームは一括変更の対象外。氏名・フリガナ・引用元IDも維持する。費用の増分・追加後の金額表示、料金計算、API、DBスキーマはこの追加改善では変更していない。

操作テストでは未変更時の戻る、編集の継続と破棄、全解除の取り消しと確定、編集済みの個別解除、保険のみ・リストバンドのみ・両方の一括変更、指定していない項目の維持、対象者の限定、確認前に保存されないこと、設定の見直しと中止を確認する。

「過去」は同じアカウントの別チームに登録した情報を指し、大会の終了日で絞ってはいない。別アカウントやテスト大会のメンバーは候補にしない。引用元が代表者でも今回のチームでは通常の選手となり、現在の代表者を置き換えない。保険・リストバンドは前回の値を初期表示するため、今回の参加条件に合わせて確認する。古い登録にフリガナがなければ、編集してから追加する。

## 重複・失敗時の動作

- 今回すでに登録した氏名・フリガナの組み合わせは「追加済み」とする。比較時は全半角・空白・英字の大小を正規化する。同じ氏名・フリガナの別人は従来の「選手を追加」で登録できる。
- 同じ引用元を同じチームへ追加する際は、元選手IDと今回のチームIDから安定した新規IDを作る。通信切断後に名前を編集して再送しても同じ引用元を二重追加せず、すでに保存した情報を上書きしない。
- 保存失敗時は選択・編集内容を画面に保持し、再試行できる。送信中は二重送信・編集・閉じる操作を止める。
- 保存は全員を1トランザクションで行う。競合は最大3回再試行し、解消しなければ再試行の案内を返す。応答は今回の全選手リストを返すため、保存後の応答だけが失われた場合も再試行で画面を同期できる。
- 複製先の選手を削除した場合は再び引用できる。元のチームの選手には影響しない。

## 権限と既存ルール

`GET/POST /api/player/history` は署名付きセッションを要求する。`x-team-id` の所有者を確認し、POSTではトランザクション内でも所有者・本エントリー状態・締切・引用元の所属を再確認する。参加者は締切後・本エントリー完了後に追加できない。既存の管理者の編集例外は維持し、管理者が代理操作する場合も対象チームの所有者の履歴だけを扱う。運営ロールには許可しない。

入力は氏名・フリガナ・保険・リストバンドだけを保存し、代表者区分・チーム状態・入金・領収書等はコピーしない。参加費・保険料は、追加された現在の選手情報を使う既存の計算式に従う。金額計算・本エントリー・代表者・認証・印刷のルール変更はない。

## 検証範囲

サービスのモックテストで所有者・別チーム・テスト大会の制限、入力検証、締切・提出後制限、代表者を引き継がないこと、重複・応答切断後の再送・競合時の再試行を確認。画面テストで選択・検索・チーム切り替え・追加前編集・失敗時の保持・送信中制御・空履歴・再読み込み・追加後の通常編集を確認。APIの未認証・偽造Cookie・他人のチームへのアクセス拒否も確認する。

実DBには接続していない。公開前に、分離した検証DBとテスト用アカウントで、元チームが変わらないこと、追加後の再読み込み、締切・提出後制限、同時操作時の競合・ロールバックを実操作で確認する。
